# Grill Me

通过一次一个关键问题，厘清方案的目标、约束、取舍和决策依赖。不要把它变成泛泛问卷，也不要在追问期间修改代码或文档。

## 工作流程

1. **确定对象**：明确要审查的方案、文档或代码范围；缺少对象时先询问。
2. **查证事实**：能从代码库或已有文档回答的问题直接查证，不重复询问用户。引用实际路径或文档作为依据。
3. **建立决策树**：列出关键分支和依赖，优先询问会阻塞后续决策的问题。
4. **逐题追问**：每轮只问一个问题，附上你的建议答案、理由和主要代价；提供选项时使用户容易作答。
5. **记录结论**：用户回答后，确认已解决的决策及其影响。出现矛盾时回到相关分支，不带着冲突继续。
6. **结束条件**：关键分支均已解决，或用户明确表示暂停/结束时停止追问。不要为凑问题而重复提问。

## 最终输出

达成共识后，给出简洁摘要：

- 已确认的决策及理由
- 已排除的方案及原因
- 仍存疑或待验证的事项
- 下一步行动及负责人（能确定时）

最后可提示用户使用 `/yo-analy extract-chat` 沉淀本次对话，但不要自动执行。
