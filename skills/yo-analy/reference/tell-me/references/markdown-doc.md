# Markdown 讲解文檔

用「完全不懂这个主题的人」能看懂的方式，把主题讲成一份**纯 Markdown 文档**：结构清晰、可复制、可嵌进 README/wiki，无需浏览器即可阅读。适用于偏「说明/用法」类主题，或用户明确要文本、要可复制、要能嵌进文档库时。

> 概念/原理/算法类若需要可视化，优先用 `simple-diagram.md` 出 HTML；系统/架构类用 `diagram.md` 出 HTML。仅当用户要 Markdown、或主题更适合文字说明时，用本文件。

## 适用场景

- 用户明确说「给我 Markdown」「纯文本就行」「贴进 README」。
- 主题偏用法/说明（如「这东西是干嘛的、怎么用」），而非需要画图才能讲清的原理。
- 需要可被版本控制 diff、可被搜索、可被复制粘贴进其它文档。

## 设计原则

- **少术语、多类比**：把陌生概念映射到日常事物（如「区块链 = 大家共用的记账本」）。
- **先讲「是什么」，再讲「怎么用」，最后讲「为什么重要」**。
- **不堆代码墙**：代码块只放最小可运行示例，且必配一行说明。
- **结构 > 篇幅**：用标题、列表、表格组织，宁可短，不可啰嗦。
- **自包含**：读完这一篇就能用起来，不要求读者先去看别的资料。

## 文档结构

按以下顺序组织（缺失的块可省略，但顺序不变）：

1. **标题**（`#`）+ 一句话概括（这玩意是干嘛的）。
2. **基本介绍**：是什么 → 类比 → 核心特征 3–5 条。
3. **基本使用**：前置/安装 → 最小示例 → 常用参数表 → 常见场景片段。
4. **小结**：一句话 takeaways + 「什么时候不该用」。

## 基本介绍（写什么）

- **一句话概括**：用不超过两行的白话讲清它解决什么问题。
- **类比**：一句话把陌生概念映射到日常事物。
- **核心特征**：3–5 条 bullet，每条「特征 + 一句白话解释」，避免术语堆叠。

## 基本使用（写什么）

- **前置/安装**：需要装什么、版本要求；若无可省略。给可直接复制的命令。
- **最小示例**：能跑的最短代码/步骤，代码块上方写一句「这段做什么」。
- **常用参数/选项**：用表格列 `名称 | 作用 | 默认/示例`，不要把全部参数都倒进来。
- **常见场景**：2–4 个真实场景片段，每个「场景 → 一段示例」。

## 排版规范

- 标题层级：`#` 文档标题、`##` 主要块、`###` 子块，不跳级。
- 代码用 fenced code block 并标语言（```bash / ```js / ```python …）。
- 表格仅用于参数/选项/对比，正文不用表格。
- 少用 emoji；不用图片（纯文本场景下图片链接易失效）。
- 命令行示例用 `bash` 代码块，输出用纯文本代码块。

## 模板骨架

```markdown
# <主题名>

<一句话概括：这玩意是干嘛的>

## 基本介绍

<一句话类比：把它想成日常的某样东西>

**核心特征：**

- <特征 A> —— <白话解释>
- <特征 B> —— <白话解释>
- <特征 C> —— <白话解释>

## 基本使用

### 前置 / 安装

\`\`\`bash
<可直接复制的安装/准备命令>
\`\`\`

### 最小示例

<这段做什么：一句话>

\`\`\`<lang>
<最短能跑的代码或步骤>
\`\`\`

### 常用参数

| 名称 | 作用 | 默认 / 示例 |
|------|------|-------------|
| `<param1>` | <干什么> | `<default>` |
| `<param2>` | <干什么> | `<default>` |

### 常见场景

- **<场景 1>**：<一句话> → `<片段>`
- **<场景 2>**：<一句话> → `<片段>`

## 小结

- <一句话 takeaways>
- 什么时候不该用：<反向边界>
```

## 输出

始终产出一个 `.md` 文件，保存为 `/docs/yo-analy/<主题slug>.md`（默认项目根目录，或用户指定路径）。纯文本、无外部依赖，可直接提交进仓库或贴进 wiki。
