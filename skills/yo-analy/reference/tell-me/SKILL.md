# Tell Me

用完全不懂该主题的人的视角，把主题讲成多图、少字、重点突出的文档。

## 工作流

1. **确认主题与输出**：主题缺失或含糊时先问一句，不猜测。用户指定输出路径或格式时优先采用。
2. **判断类型并选参考**：一个主题可命中多种类型，按需要加载对应参考，但只为用户需要的形态生成文件。
   - 概念/原理/算法类 → 读 `references/simple-diagram.md`，用 `resources/simple-template.html`。
   - 系统/架构/数据流类 → 读 `references/diagram.md`，用 `resources/template.html`。
   - 说明/用法类，或用户明确要求 Markdown / 纯文本 / 贴进 README → 读 `references/markdown-doc.md`，产出 Markdown。
3. **生成文档**：按所选参考产出对应形态。HTML 必须自包含，CSS/SVG 内嵌，不依赖远程资源；Markdown 同样少术语、少代码墙。
4. **保存**：默认写入项目根目录 `docs/yo-analy/<主题slug>.html` 或 `.md`，不要使用以 `/` 开头的绝对路径。目标已存在时先询问覆盖、更新或更换路径。
5. **验证并交付**：HTML 在可用浏览器中检查渲染、SVG、文字溢出和资源加载；无法检查时明确说明未做浏览器验证。返回实际文件路径和验证状态。

## 内容要求

- 用类比、分层和分步讲清“是什么 → 怎么工作 → 为什么”。
- 图示必须服务于对应概念，不能用装饰图代替解释。
- 不堆术语，不贴大段代码，不写成教科书；涉及具体代码或系统时先读取实际资料，不虚构架构。
