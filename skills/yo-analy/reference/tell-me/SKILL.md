用「完全不懂这个主题的人」的视角，把主题讲成一份**自包含 HTML 文档**：多图、少字、重点突出、可直观理解。

## 工作流

1. **确认主题**：拿到要解释的主题。若用户没给主题（或主题含糊），先问一句再动手，不要瞎猜。
2. **判断类型并选参考**：一个主题可同时命中多种类型，按命中的类型逐条加载对应参考、产出多份文档（如某系统既要架构图又要用法说明，则同时读 `diagram.md` + `markdown-doc.md`）。
   - **概念/原理/算法类**（如「区块链是什么」「TCP 三次握手」）→ 读 `references/simple-diagram.md`，用 `resources/simple-template.html` 模板。
   - **系统/架构/数据流类**（如「这个系统的整体架构」）→ 读 `references/diagram.md`，用 `resources/template.html` 模板。
   - **说明/用法类**（如「这东西是干嘛的、怎么用」），或用户明确要 Markdown / 纯文本 / 贴进 README 时 → 读 `references/markdown-doc.md`，产出 Markdown 文档。
3. **生成文档**：按所选参考产出对应形态——自包含 HTML（内嵌 CSS/SVG，浏览器直接打开即可渲染）和/或纯 Markdown，每种类型各一份。
4. **交付**：HTML 保存为 `/docs/yo-analy/<主题slug>.html`，Markdown 保存为 `/docs/yo-analy/<主题slug>.md`（默认项目根目录，或用户指定路径），并回显文件路径。

## 应该做 / 禁止做

- **应该做**：少文字、多图，用类比/分层/分步讲清「是什么 → 怎么工作 → 为什么」；即使画架构图也保持外行能看懂。Markdown 形态同样保持少术语、外行能懂，不堆代码墙。
- **禁止做**：堆术语、贴大段代码、写成教科书。
