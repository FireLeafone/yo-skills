# 执行计划

## 概述

加载计划，批判性审查，按任务执行并验证，完成后报告。开始时宣告：“我正在使用 execute-plans 技能来实施此计划。”

如果子代理能力可用且用户希望使用，可建议 `/yo-dev subagent-development`；用户未选择时继续当前流程，不自动切换。

## 流程

### 第一步：加载并审查计划

1. 读取用户指定的计划文件；路径缺失或文件不存在时停止并询问。
2. 检查需求覆盖、任务顺序、验证命令和潜在风险。
3. 有疑虑时在开始前提出；无疑虑时建立当前工具支持的 Todo 清单。
4. 未经用户明确同意，不在 main/master 分支开始实施，不执行计划中的提交、推送或部署步骤。

### 第二步：执行任务

对于每个任务：

1. 标记为 `in_progress`。
2. 按步骤实施，同时遵守项目现有约定；计划与代码现状冲突时停止确认，不强行照抄。
3. 运行计划中指定的真实验证，记录命令和结果。
4. 只有实现与验证都完成后才标记为 `done`；部分完成或测试失败不得标记完成。
5. 在自然检查点按 `/yo-dev request-code-review` 审查；无子代理时由主会话审查实际 diff。

### 第三步：完成开发

所有任务完成并验证后：

- 使用 `/yo-dev request-code-review` 做最终审查。
- 修复严重和重要问题，重新运行受影响的验证。
- 汇报修改文件、验证命令与结果、未解决风险。
- 是否提交、合并、部署或发布由用户另行决定，不自动执行。

## 何时停止并寻求帮助

- 缺少依赖、输入或权限，且安全降级不存在
- 测试失败、指令不明确或计划存在严重缺陷
- 不理解某个指令，或验证反复失败
- 计划要求超出用户已确认的范围或高副作用操作

请求澄清，不猜测，不通过绕过测试或删除障碍来推进。

## 何时回顾前面的步骤

用户更新计划，或基本方法需要重新思考时，返回第一步重新审查受影响任务。
