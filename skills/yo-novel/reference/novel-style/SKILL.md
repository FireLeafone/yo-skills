# novel-style

从一本已有小说中"逆向工程"出一份结构化、可复用的写作风格指南。目标是让后续的 `novel-write` 能像使用内置风格（`style-guide.md` / `style-ancient.md` / `style-web-novel.md`）一样，直接引用这份写作手册来仿写同款气质的文字。

## 核心理念

这份技能不是写一篇"读后感"，而是产出一份**工程化的写作执行手册**。它要回答的问题是："如果另一支笔想写出和这本书一样的味道，它需要遵守哪些约束？" 因此每一条结论都要尽量落到**可执行、可检验**的层面（句式、节奏、视角、用词 register、信息释放时机），而不是停留在"文笔优美、感人至深"这类无法落地的形容词。

诚实是这份文档的底线。两条硬约束：

- **不得伪造引文**：只有用户提供的例文里真实出现的句子，才能作为原文引文出现（用引号标出并注明出自第几段）。其余一律转述或概括，绝不冒充原著原话。
- **置信度要诚实**：当某一维度证据薄弱（没例文、又搜不到可靠评论）时，要么不写、要么明确标注该维度置信度低，绝不把推断包装成确凿结论。一条假的"原著特征"比缺失更危险——它会污染所有后续仿写产出。

外部资料可溯源即附来源链接，便于用户复核；抓取到的页面要点用自己的话转述。

## 输出原则：写给写作 agent，不是写文学评论

本技能的产出首先是一份**可执行的写作手册**，其次才是一份风格分析。判断标准不是“分析得深不深”，而是“`novel-write` 拿着它能不能直接写出像样的段落”。

- **执行卡置顶**：文档开头必须是 1 页以内的「风格执行卡」，用祈使句列出视角、主角、语言、对话、场景、情感、禁止项。分析、置信度、来源放附录。
- **每条结论落到动作**：不写“文笔冷峻”，写“情感高点用陈述句和动作，不用感叹句”；不写“配角鲜明”，写“每个常设角色给自称+口癖+句长三件套”。
- **场景配方 + 人物声纹 + 写时自检是必需章节**，不能只有维度分析。
- **正例/反例成对**：每个关键技巧至少给一个“不要这样写”和一个“改成这样写”。
- **用写作时的口吻**：祈使句、短句、可检查；少用“本书的特征是……”，多用“写的时候要……/不要……/自检……”。

## 输入

调用本 skill 需要两样东西：

1. **小说名**（必需）。书名要尽量准确，含作者更佳（同名小说很多）。如果用户只给了一个模糊说法（如"那本写三体的"），先和用户确认具体书名与作者。
2. **示例文章内容**（强烈建议，但允许缺省）。一到数段该小说的原文片段，是唯一可逐字引用的证据来源。可以是直接贴在对话里的文本，也可以是文件路径。如果没有例文，风格提取将主要依赖网评与模型对该作的文学常识，"语言文字质感""对话风格"等需要原文佐证的维度置信度会偏低——这种情况要提前告知用户。

可选输入：用户指定只提取其中几个维度、指定输出文件名、指定输出目录。

## 输出位置

- 默认输出到项目根目录下的 `presets/styles/【书名】-style-skill.md`。文件名中的 `【书名】` 用书名本身替换（保留全角方括号 `【】`，例如 `【三体】-style-skill.md`）。如果用户偏好不带括号或改用《》，按用户要求执行。
- 如果 `presets/styles/` 不存在，创建它。这条路径与 `novel-create` 的 `presets/` 约定保持一致，便于集中管理。
- 如果目标文件已存在，**必须先询问用户是覆盖、合并还是跳过**，禁止直接覆盖——风格文档往往是反复迭代的产物。
- 产出后，告诉用户：若希望在 `novel-write` 中直接引用，可把该文件复制/软链到 `novel-write/references/`，或直接在写作时指定 `presets/styles/【书名】-style-skill.md` 作为风格参考；`novel-write` 优先使用用户指定的风格。

## 工作流程

### 1. 理解需求与确认门槛

先与用户对齐，**不要拿到书名就闷头检索**。需要确认：

- 书名与作者是否准确（尤其同名作品）。
- 是否提供了例文；若有，是文本还是文件路径。读取文件内容。
- 用户是否只关心部分维度（默认全量，见 `references/dimensions.md`）。
- 输出文件名与目录是否用默认值。
- 是否需要中英双语或仅中文。

**确认门槛（硬性，但允许快速路径）**：

- **常规路径**：向用户展示一份简短的"提取计划"——将检索哪些方向的资料、会覆盖哪些维度、输出到哪个文件、预计例文实证能支撑哪几条。等待用户明确回复（"确认/开始/ok"）后再继续。
- **快速路径**：如果用户已明确给出书名+例文+维度范围+输出路径，可直接进入 Step 2，但仍需先告知一句"将输出到 <路径>"并等待用户确认落盘路径。

计划示例：

```markdown
将为《三体》生成写作执行手册：
- 检索方向：豆瓣长评、知乎文学评论、主流媒体书评
- 覆盖维度：叙事视角、全书风格气质、推进节奏、语言文字质感、冲突与伏笔、世界环境温度、信息释放、对话风格、主角与主要配角性格
- 例文：你贴的三段原文（用于语言质感、对话等维度的实证）
- 输出：presets/styles/【三体】-style-skill.md

确认后开始。
```

### 2. 联网检索评价

使用当前宿主可用的网页搜索与页面抓取工具检索外部评价。目的是补全例文无法覆盖的宏观特征（气质、节奏结构、伏笔评价、读者共识），并交叉验证对例文的判断。工具不可用或检索失败时按本节降级规则处理，不虚构搜索结果。

建议检索方向（按优先级，多路并行）：

- `<书名> 书评 / 长评` —— 读者共识与情感反应。
- `<书名> 写作风格 / 叙事 / 文学分析` —— 偏技术的评论。
- `<书名> 作者 文风 / 叙事特点` —— 作者层面的风格定位。
- `<书名> 伏笔 / 结构 / 节奏` —— 结构层面。
- `<书名> 人物 分析 / 角色塑造` —— 人物维度。
- 英文资料（若该书有外译/外评）：`<title> review literary analysis`、`<title> narrative style`。

检索要点：

- **多源交叉**：单篇评论可能带偏见或事实错误。关键结论尽量由两个独立来源印证，否则降低置信度。
- **中文作品注意**：搜索引擎对中文小说覆盖可能有限。对豆瓣、知乎、专业书评站的内容，用当前可用的页面抓取工具读取具体页面；抓取失败时转而依赖例文。
- **可溯源**：外部结论附来源 URL，页面要点用自己的话转述，不伪造成原文引文。
- **不可检索时的降级**：搜不到有价值的外部评价时，明确告知用户并转向例文；文学常识只能作为低置信度假设，不得伪装成已核实事实。

### 3. 例文细读

把用户提供的例文当作“指纹”，做细粒度拆解：

- 句式、复句嵌套、用词语域、修辞偏好与意象
- 视角、叙述距离、对话辨识度和潜台词
- 人物外貌、动作、心理及他人反应如何共同塑造形象
- 场景切换、时间跳跃、视角转换、感官细节与信息释放

边读边标记有辨识度的技巧样本并记录例文段落编号。对话样本要保留必要的上下文和动作节拍；转场样本要保留切换前后的衔接句，避免只截取半句而失去技巧结构。

只有例文里真实出现的句子才能作为引文，并注明“见例文第 X 段”。样本太短时不计算或推断全书比例，只描述当前样本中可观察的现象。

### 4. 多维度提取与写作动作化

按 `references/dimensions.md` 逐条提取。每个维度不要只写“特征描述”，必须产出四件事：

- **写的时候怎么做**：2–5 条祈使句，能直接指导下一段。
- **不要怎么做**：2–3 条常见跑偏。
- **自检问题**：1–2 个写作时能回答的问题。
- **证据/置信度**：一句话说明例文/外部评论/推断的证据强弱，放到附录。

“可仿写要点”必须通过这条硬检验：**把这条交给一个没读过原著的写作 agent，它能否据此判断“我这一段写得像不像、该不该这样写”**。只有实际统计了具有代表性的样本时才给比例或数值，不使用“短句占比 ≥40%”之类无依据的精确指标。

#### 4.1 技巧例证卡

发现对话、人物描写、转场或其他有辨识度的写作技巧时，按 `references/technique-examples.md` 制作“技巧例证卡”，形成**原作证据 → 机制拆解 → 写的时候怎么做 → 正例/反例 → 自检**的链条。例文充分时优先选择 4–8 个最能代表本书的技巧；证据不足时按实际数量输出，不为覆盖类别而硬凑。

仿写示例必须使用新人物、新情境演示同一技巧，并明确标注“生成示例（非原文）”。外部评论只能支持技巧判断，不能冒充原作片段；没有例文时不得虚构引文。

#### 4.2 场景配方与人物声纹

这两节是 `novel-write` 动笔时最常用的部分，不能省略。

- **场景配方**：至少覆盖 4–6 类本书的高频场景（如制度压迫/征收、官场对话、市井信息、战斗/守城、场景转换、章末钩子）。每类给出：目标、节拍（1→2→3→4）、视角、语言、正例（生成，非原文）、反例、自检。证据不足时按实际能支撑的类型输出，并标注缺口，不为凑数虚构。
- **人物声纹表**：覆盖 3–8 个主要角色。每人给出：功能、自称/称呼、句长/语气、口癖/用词、示例台词（生成，非原文）、不要写成。示例台词只模仿声纹，不抄原著句子；证据不足时按实际数量输出。

场景配方和人物声纹的格式见 `references/output-template.md`，观察点见 `references/dimensions.md`。

### 5. 防跑偏清单（写时自检）

仿写最大的风险不是“写不像”，而是“写过头”——把原著某个特征无限放大、或把不适合该场景的特征硬套上去。本步骤要产出一份针对**这本书**的防跑偏清单。

方法：基于 `references/anti-drift.md` 的通用跑偏框架，结合第 4 步提取出的维度特征，逐条推导“仿写这本书时最容易犯的错”。每条采用统一格式：

```markdown
- 【跑偏点】<一句话点名风险>
  - 典型表现：<具体怎么就跑偏了>
  - 自检问题：<写作时能直接回答的一个问题>
  - 修正动作：<改哪一句/哪一段，怎么改>
```

例如，仿写一本硬科幻时常见跑偏：“把设定当科普，人物沦为设定工具人”——典型表现是连续两页都在讲技术原理、角色没有动机；自检问题是“这一段谁在着急、为什么着急”；修正动作是“把设定披露挂到角色的动作上，超过 3 句纯设定就删到 1 句或拆进对话”。

清单控制在 6–10 条，聚焦这本书**特有**的高频风险，不要泛泛而谈“注意不要流水账”这种放之四海皆准的话。清单要能直接用于写完后的 5 分钟自检。

### 6. 生成写作执行手册

按 `references/output-template.md` 的结构组装最终文档，写入 `presets/styles/【书名】-style-skill.md`。文档标题写成“【书名】写作风格执行手册”，不要写成“风格档案/文学分析”。组装时：

- **最前面放 1 页以内的「风格执行卡」**：一句话风格 + 视角/主角/语言/对话/场景/情感/禁止项，全部用祈使句。
- **正文按写作动作组织**：叙述视角与信息边界 → 主角决策引擎 → 人物声纹表 → 语言执行参数 → 场景配方（4–6 类）→ 伏笔与信息释放 → 写时自检清单 → 防跑偏。
- **人物声纹按人做成表**：功能、自称/称呼、句长/语气、口癖/用词、示例台词（生成，非原文）、不要写成。
- **场景配方按场景类型做成“节拍 + 正例 + 反例 + 自检”**，让 agent 能直接照着写一段。
- **分析、置信度、技巧库、参考来源放附录**，不要占正文篇幅。
- **末尾留“适用场景”与“与内置风格的关系”**，帮助 `novel-write` 判断何时该用这份手册。
- 在顶部写一句使用说明：先读执行卡，写具体场景读对应配方，交稿前跑自检清单。

### 7. 自检与交付

落盘前过一遍自检：

- [ ] 没有伪造原文引文——所有引文都真实来自用户提供的例文并注明出处。
- [ ] 外部资料结论为转述并附来源链接，没有伪造引文。
- [ ] 置信度诚实标注，没有把薄弱证据写成确凿结论。
- [ ] **执行卡在 1 页以内**，且全部是可执行的祈使句/可检查项，不是形容词堆砌。
- [ ] **一个没读过原著的写作 agent，只看执行卡 + 相关场景配方 + 人物声纹，能否写出 800 字像样的段落？**
- [ ] 每个核心维度都有“写的时候怎么做 / 不要怎么做 / 自检问题”，不是只有“特征描述”。
- [ ] 场景配方至少 4–6 类（证据不足时按实际数量并标注缺口），每类有目标、节拍、视角、语言、正例、反例、自检。
- [ ] 人物声纹表覆盖 3–8 个主要角色（按实际证据），示例台词模仿声纹但不抄原文。
- [ ] 技巧卡包含“原作证据 → 机制 → 写的时候怎么做 → 正例/反例 → 自检”，生成示例标注“非原文”。
- [ ] 防跑偏清单 6–10 条，每条有“典型表现 / 自检问题 / 修正动作”。
- [ ] 分析、置信度、来源已移到附录；正文只留写作时用得上的内容。
- [ ] 输出文件路径与用户确认的一致；若曾存在同名文件，已按用户选择处理。

自检通过后写入文件，并向用户回报：输出路径、整体置信度、哪些维度证据不足需要用户补例文或补资料。

## 何时不要用本 skill

- 用户想从零设计一本**全新**小说的风格——那是 `novel-create` 的职责。
- 用户想直接**写正文**——把已提取的写作手册交给 `novel-write`。
- 用户只想随便聊聊一本书好不好看、不打算落盘成可复用文档——直接聊即可，不必调用本 skill。
- 用户提供的"小说"其实是没有定型的零散点子，无原作可提取——本 skill 依赖一本**已存在**的原著作为分析对象。
