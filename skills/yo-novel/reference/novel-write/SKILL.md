# novel-write

根据小说已有的大纲、人物、世界观和进度文档，撰写或续写单章正文，并保存为 Markdown 文件。

## 什么时候用

- 用户说"写第 X 章"、"帮我写一章"、"续写小说"、"开始写正文"
- 用户提到"novel chapter"、"write chapter"、"continue novel"、"next chapter"
- 用户已创建小说项目，需要基于 `presets/` 中的设计文档产出 `chapters/` 下的正文

以下情况不用:

- 用户还没有小说项目，想从零开始搭建结构（使用 `novel-create`）
- 用户只想做前期设计、大纲、人物设定，不需要落盘正文（使用 `novel-design`）
- 用户只是闲聊点子、询问写作技巧，没有明确要写某一章

## 输出位置

- 默认写入项目根目录下的 `chapters/` 目录，文件名为 `NNN-[章节名].md` 或用户指定的文件名。
- 如果用户明确指定了其他路径或文件名，按用户要求执行。
- 🔴 **CHECKPOINT（防覆盖）**：如果目标文件已存在，🛑 STOP — 必须先询问用户是覆盖、合并还是跳过，禁止直接覆盖。

## 硬性规范

- **格式**：Markdown。
- **篇幅**：每章不少于 **2000** 字，不多于 **4000** 字。
- **章节状态**：写完后更新 `progress.md`，将该章标记为"已完成"或对应状态。
- **不使用占位符**：章节内容必须完整成文，不能使用"（此处省略）"、"待补充"等占位符。

## 工作流程

### 1. 收集写作意图（动笔前一次性对齐）

在读取文档前，先从用户输入中提取或向用户确认以下关键参数：

- **新章 / 续写**：是新写一章，还是续写某章断点。
- **章节号与文件名**：目标章节号、`chapters/` 下文件名。
- **字数**：默认 2000-4000，用户另有要求则按用户。
- **写作风格**：用户指定风格优先；未指定则留待 Step 3 由你推荐。
- **叙事视角**：第一人称 / 第三人称限知 / 第三人称全知。
- **本章核心任务**：本章要推进的情节或冲突（可留待读大纲后补全）。

判定路径：

- **常规路径**：用户只给了章节号，未给齐情节/风格等 → 走完整 Step 2-3，Step 3 做计划确认。
- **快速路径**：用户已明确给出情节、风格、字数等 → 可跳过 Step 3 的详细计划，但 Step 3 仍须确认落盘路径。

如果用户未指明章节号：查看 `progress.md` 中标记为"待写"的下一章，列出最近 3 章状态询问用户写哪一章；用户仍不指明则默认"最后一章 +1"并报告此默认值。

### 2. 读取项目文档与上文回溯

按以下顺序读取项目根目录下的文档：

1. `presets/outline.md` — 故事大纲，锁定目标章节的细纲与爽点安排。
2. `presets/characters.md` — 登场人物及其状态。
3. `presets/world.md` / `presets/settings.md` — 世界观与其他设定。
4. `progress.md` — 确认目标章节状态，回顾上一章结尾以保证衔接。
5. `rules.md` / `AGENTS.md` — 项目特定的写作规范。

如果缺少关键文档（`outline.md` 或 `progress.md`），🔴 **CHECKPOINT（缺文档）**：🛑 STOP — 先告知用户缺失内容，询问是否继续或补充；用户坚持继续则仅基于已读文档写，报告末尾标注"未对齐大纲"。

**上文回溯**：若目标章节不是第一章，读取 `chapters/` 下最近 1-3 章内容，记录关键剧情、伏笔、人物状态与未解决冲突，避免"吃书"。

**续写判定**：如果 `progress.md` 标记某章为"写作中"，或目标文件内容明显未完，走续写路径——从断点继续，承接上文情节、氛围、人物语气与叙事节奏。🔴 **CHECKPOINT（续写确认）**：续写前先向用户说明将续写的文件与断点位置，🛑 STOP 等用户确认。断点无法定位则询问用户从哪一段续起。

### 3. 对齐方向并动笔前确认（单一确认门槛）

向用户展示本章计划，包含：

- 目标章节号与文件名
- 本章在大纲中的位置与核心任务
- 计划登场的主要人物
- 本章的关键冲突 / 爽点 / 转折点
- 拟采用的写作风格（见下方"风格选择"）
- 文件保存路径

如本章场景超过 3 个、多线交织，或用户对本章情节只有模糊想法，可在此附带生成章节模板（场景清单、情绪曲线、关键对话提示，详见 `references/chapter-write.md`）作为计划的一部分。

🔴 **CHECKPOINT（动笔前确认）**：🛑 STOP — 展示完上述计划后，必须等待用户明确回复（如"确认""开始""ok"）后再进入 Step 4 撰写。未获确认不得动笔。

**快速路径**：用户已在 Step 1 给齐情节/风格/字数 → 跳过详细计划，但本门槛仍生效：只须告知用户将写入的文件路径并等待确认。

#### 风格选择

优先使用用户指定的风格。如果用户未指定，从内置风格中选一种最贴合本章氛围的，给出推荐并说明理由（依据本章情绪基调、场景规模、人物关系与小说类型）；不要一次性列出所有风格让用户挑选。详细风格定义与适用题材见 `references/style-guide.md`，古风 / 网文 / 历史题材另有 `style-ancient.md` / `style-web-novel.md` / `rule-history.md`。

### 4. 撰写正文

按 Step 3 确认的内容方向与风格撰写。核心必须项：

- 叙事视角在本章内保持一致。
- 情节逻辑自洽，不违背已有设定。
- 按起承转合组织：起（引入）→ 承（推进）→ 转（转折）→ 合（落点 / 钩子）。
- 埋设或回收伏笔，服务后续剧情。

场景构建、对话、动作表情、节奏控制、悬念伏笔等技巧见 `references/writing-techniques.md`。

### 5. 自检

写完后自查。优先使用项目根目录的 `checked.md`（若存在）逐项检查；没有则按下方清单：

- [ ] 字数在 2000-4000 之间（优先用项目内 `count_words.py`，缺失则统计 CJK 字符数）。
- [ ] 没有出现"（待补充）""（略）"等占位符或未完成段落。
- [ ] 目标章节在大纲中的任务已完成。
- [ ] 登场人物的性格、动机与 `characters.md` 一致。
- [ ] 没有与 `world.md` / `settings.md` 矛盾的设定。
- [ ] 与上一章结尾衔接自然。
- [ ] 关键伏笔已埋下或回收，且逻辑通顺。
- [ ] 对话、动作、表情描写足够，没有大量直接陈述。
- [ ] 章节末尾有情绪落点或下一章钩子。
- [ ] 减少 / 移除 AI 味，参考 `references/rm-ai-style.md`。

如发现问题，先修正再保存。

### 6. 保存与报告

- 将正文写入 `chapters/` 下指定文件。
- 更新 `progress.md` 中该章节状态。
- 向用户报告：文件路径、实际字数、本章核心事件、下一章建议或待填伏笔。

## 失败模式兜底

正文 CHECKPOINT 未覆盖的场景按下表处理，禁止静默跳过：

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| `chapters/` 目录不存在 | 自动创建目录再写入 | 创建失败 → 报告路径权限问题，正文暂存为草稿回显 |
| 写完字数 <2000 | 补足场景 / 对话到区间内 | 难以扩充 → 🛑 STOP 报告实际字数，询问用户接受或重写 |
| 写完字数 >4000 | 拆分章节或精简至区间内 | 无法拆分 → 🛑 STOP 报告，询问用户是否破例保留 |
| 自查发现吃书 / 设定矛盾 | 定位矛盾点改写该段 | 改动牵连太大 → 🛑 STOP 列出矛盾，询问用户取舍 |

## Common Mistakes

- 把正文写入 `presets/` → 正文应放入 `chapters/`。
- 视角中途切换却无明确过渡 → 同一章内保持视角一致，切换时要有过渡。
- `count_words.py` 不存在时仍按估算落盘 → 缺失则改用 CJK 字符统计，写完再校验字数区间。
