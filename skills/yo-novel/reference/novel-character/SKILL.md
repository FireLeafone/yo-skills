# 人设与群像设计

把人物设计落实为可指导后续写作的角色档案，而不是堆砌标签。每个设计选择都应能解释角色的目标、行为、关系和变化。

## 工作流程

1. **确定项目与范围**
   - 确认本次处理主角、配角、反派、关系或弧光中的哪些内容。
   - 用户指定小说项目时，先读 `presets/characters.md`、`presets/outline.md` 和相关世界设定；不存在时说明将基于用户输入设计。
   - 信息不足时只询问会影响人物核心动机的关键问题，不机械追求完整问卷。

2. **按需读取参考**
   - 主角性格：`references/protagonist-tags.md`
   - 配角功能：`references/supporting-roles.md`
   - 反派塑造：`references/antagonist-templates.md`
   - 人物关系：`references/relationship-patterns.md`
   - 人物弧光：`references/character-arc.md`
   - 风格特点（口头禅、习惯性动作等标志性言行）：`references/style-signatures.md`
   - 能力、等级、职位、工具及阶段变化：`references/power-progression.md`

   只加载本次涉及的文件。标签用于启发，不得把多个冲突标签无差别堆到同一角色上。

3. **形成设计方案**
   每个主要角色（主角、主要配角、核心反派）至少明确：
   - 外在目标、内在需求、核心恐惧或矛盾
   - 性格主导特征与反差点，以及各自在行动中的表现
   - 在情节中的功能、与其他角色的利益或情感关系
   - 关键选择、变化节点和弧光类型
   - 口头禅、语言习惯、习惯性动作等风格特点：与性格标签和小说风格设定互相解释，每个主要角色控制在 1 个核心口头禅加 2–3 个习惯性动作，并标注随弧光的演变
   - 能力（技能、知识）、等级、职位和关键工具：写明现状与来历，等级和职位沿用项目世界设定的既有体系，并给出随大纲阶段的推移方式（触发事件与代价）

   对关键方向提供 2–3 个有实际差异的选项及代价；用户已有明确设定时直接沿用，不强行重新设计。

4. **检查一致性**
   - 行为是否能由目标、经历和性格解释
   - 人物功能是否重复，配角是否只有工具作用
   - 反派是否有可理解的动机和有效行动，而非仅“坏”或“强”
   - 关系变化是否有事件支撑，弧光是否与大纲节点对应
   - 历史题材中的借鉴是否经过用户认可，不把历史人物事迹直接拼贴成角色经历
   - 口头禅和习惯动作是否与性格、经历互相解释，放进本书任何一章是否出戏；群像对白遮住名字能否区分说话人
   - 等级、职位是否与项目世界体系的名称和上限一致；能力是否与经历、性格互相解释，主要角色是否有明确短板
   - 能力、等级、职位、工具的变化是否由大纲中的具体事件触发并有代价，而非随时间自动升级；变化表与弧光节点、伏笔是否对应
   - 反派能力是否对主角当前阶段形成实际压制并留出与主角成长方向对应的缺口；主角升级时反派是否同步变化，强弱对比是否失衡；配角能力与主角是否重叠

5. **保存与交付**
   - 默认更新项目的 `presets/characters.md`；只讨论或用户不要求落盘时直接在对话中交付。
   - 写入前展示路径和将影响的角色；文件已存在时先读取并增量更新，不整份覆盖。存在冲突或需覆盖既有设定时等待用户确认。
   - 检查大纲、世界设定和伏笔是否受影响；需要同步修改其他文件时先列出并确认。

## 输出契约

每个主要角色（主角、主要配角、核心反派）使用可检索的小节，至少包含：角色定位、目标与动机、性格及行为证据、风格特点、能力与成长、关系、弧光、写作注意事项。风格特点至少给出核心口头禅、变体和习惯性动作。能力与成长至少给出当前等级、职位与资源、核心能力及来历、明确短板、关键工具，以及阶段变化表（触发事件对应大纲节点并注明代价）；写实或无体系题材可用实力参照替代等级。最后列出与既有设定的冲突和仍需用户决定的事项。

## Gotchas

- 不用“高冷 + 腹黑 + 病娇 + 佛系”等标签数量代替人物逻辑。
- 矛盾人格必须有稳定的核心动机和触发条件，不能把自相矛盾当作复杂。
- 不为每个配角安排牺牲、背叛或反转；功能服务故事，避免过度设计。
- 修改角色后必须检查相关大纲和关系，不让其他文档保留旧设定。
- 口头禅和习惯动作宁少勿滥：高频复读会把角色喜剧化，严肃题材只在关键节点出现并保留变体。
- 风格特点不做脱离性格与题材的噱头：古风背景不出现现代口癖；项目已有 novel-style 人物声纹表时必须与之同调。
- 能力、等级、职位、工具不用数值面板代替来历：每项都要能反推出经历或事件，答不上来就删。
- 升级不免费：每次变化都有触发事件和代价；世界设定未定义等级体系时先与用户确认补世界设定还是用实力参照，不自造体系；群像不配等级表，避免等级通胀。
- 配角和反派不陪跑也不站桩：配角的变化服务自身弧光，反派与主角镜像同步；主角单方面变强会让威胁感和配角存在感一起塌掉。
