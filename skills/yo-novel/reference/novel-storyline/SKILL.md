# novel-storyline

将一部小说（或书籍、长文）的人物与情节提炼为一张「Git 分支式人物进程图」：以主角进程线为主线，核心人物彩色线、次要人物灰线，共同经历的事件处多线交汇，最终产出一个零依赖、可直接用浏览器打开的单文件 HTML。

## 输出

- 单个自包含 HTML 文件，默认命名为 `<书名>-storyline.html`，输出到当前工作目录（用户可指定路径）。目标已存在时先询问覆盖、更新或更换文件名。
- 渲染由模板资产 `assets/character-lines-template.html` 完成，只需抽取数据并安全注入模板，不重写渲染代码（除非用户明确要求调整样式）。来源不足时只能生成明确标注的节选/演示版，不得补齐虚构情节。

## 工作流程

### 1. 获取原文与结构

根据来源选择一种方式：

- **用户提供文本文件**：直接阅读。内容较长时，先用 `Grep '^#'` 之类的方式列出章节结构，再分批阅读，避免一次性塞入全文。
- **novel 项目**（novel-create 创建的项目）：读 `presets/characters.md`、`presets/outline.md`、`progress.md` 获取人物与情节，比读正文更快更准。
- **名著 / 公开书籍**（如四大名著）：联网检索分回梗概与人物介绍来整理数据，并在 DATA 的 `subtitle` 中注明"基于公开资料整理"。

### 2. 抽取人物（characters）

为每个人物确定：

- `id`：英文小写标识；`name`：姓名。
- `role` 分级，决定线的样式：
  - `main` 主角，全书只有一条主线，用最醒目的颜色并自动加粗；
  - `core` 核心人物（与主线深度交织，如对手、挚爱、挚友）；
  - `support` 配角（有独立弧线但戏份有限）；
  - `minor` 次要/过程人物，不填 `color`，自动渲染为灰细线。
- `color`：鲜明且互相区分的颜色。主角建议红色系，其余错开色相。
- `first`：出场回目/章节号——**线的起点由此决定**，这是图表的核心信息之一，务必从原文确认而非估算。
- `end` / `endNote`（可选）：退场回目与说明（如"病逝"、"出家"），线在该处画终止符收尾。

**数量控制**：彩色线（main+core+support）建议不超过 10 条，其余归入 minor 或省略。线太多会糊成一团，宁可少而清晰；拿不准分级时向用户确认。

### 3. 抽取事件（events）

- 选取**改变人物关系或命运走向的关键节点**，20–40 个为宜，不要把每章流水账都放上去。
- `chapter`：时间轴坐标，必须是数字。优先用真实回目/章节号；没有章节概念的文章用事件序号（1..N）。同一回目有多个事件时用小数错开（如 27 和 27.5）。
- `title`：简短事件名（会显示在图上，8 字以内为佳）；`desc`：1–2 句描述（tooltip 用）。
- `importance`：1–3，决定节点大小。重大转折/高潮给 3，日常过渡给 1。
- `characters`：参与人物 id 列表。**多人共同经历的事件放多个 id**，渲染时各线会在该处交汇为一个节点再分开——这是"共同经历"的表达手段，也是这张图的灵魂，注意把真正的群像戏（宴席、大战、变故）标全。

### 4. 生成 HTML

用小脚本完成注入，避免手写长 JSON。模板路径从本 `SKILL.md` 所在目录解析；写入前再次检查目标是否存在及用户选择。JSON 必须转义 `</`，防止原文中的 `</script>` 提前结束脚本：

```bash
python - <<'EOF'
import json
from pathlib import Path
skill_dir = Path('<本技能目录>')
output = Path('<书名>-storyline.html')
tpl = (skill_dir / 'assets/character-lines-template.html').read_text(encoding='utf-8')
data = { ... }  # 抽取好的数据
payload = json.dumps(data, ensure_ascii=False, indent=2).replace('</', '<\\/')
html = tpl.replace('__DATA_JSON__', payload)
if '__DATA_JSON__' in html:
    raise SystemExit('模板数据占位符替换失败')
output.write_text(html, encoding='utf-8')
EOF
```

脚本失败或输出仍含占位符时停止交付，不保留看似成功的 HTML。

## 数据结构（注入 `__DATA_JSON__` 的对象）

```js
{
  title: '书名',
  subtitle: '可选,副标题/数据来源说明',   // 显示在标题旁
  chapterMax: 120,                        // 时间轴最大值(全书回目数)
  chapterUnit: '回',                       // 可选,时间轴单位,默认"回";文章可填"章""节"
  characters: [
    { id: 'baoyu', name: '贾宝玉', role: 'main', color: '#e03131', first: 1 },
    { id: 'daiyu', name: '林黛玉', role: 'core', color: '#1971c2', first: 1, end: 97, endNote: '泪尽而逝' },
    { id: 'liulaolao', name: '刘姥姥', role: 'minor', first: 6 }  // minor 省略 color → 灰线
  ],
  events: [
    { id: 'e1', chapter: 3, importance: 3, title: '宝黛初会',
      desc: '林黛玉进贾府,与宝玉初见。',
      characters: ['baoyu', 'daiyu', 'xifeng'] }   // 多人 → 交汇节点
  ]
}
```

注意：`characters` 数组的顺序即车道从上到下的顺序，按 main → core → support → minor 排列；多人事件节点的颜色取参与者中排序最前者，所以主角排最前可让交汇节点优先呈现主线色。

## 5. 验证

生成后自查再交付：

1. **数据与语法**：核对人物 id 引用、章节范围和数据来源；抽出真实数据替换后的 `<script>` 内容运行 `node --check`。Node.js 不可用时明确标注未做语法检查。
2. **视觉**：有浏览器时打开实际 HTML，检查人物线起点、交汇、图例显隐、标签重叠和资源加载；可用无头浏览器时保存截图并查看。没有浏览器时只交付已通过的数据/语法检查，明确写出“未做浏览器视觉验证”。
3. 报告文件路径、实际执行的检查和未验证项；无截图时不得声称已检查截图或交互。

## Gotchas

- **不要虚构情节**：对不熟悉的作品，联网检索核实人物出场/退场与关键事件；数据只是节选或演示性质时，在 `subtitle` 里写明。
- **同回目多事件**：用小数 chapter 错开（27 / 27.5），否则节点完全重叠。
- **事件过密**：开篇事件扎堆导致标签重叠时，优先精简低 importance 事件，而不是缩小字号。
- **人物突然消失**：有明确退场的人物务必给 `end`，否则线会拖着尾巴到全书结尾，误导读者。
- **非小说文本**（散文、传记、报道）：同样适用——人物换成主体对象，事件换成关键节点，`chapterUnit` 改为合适单位。
